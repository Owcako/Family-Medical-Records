## 1. 用户能走通的完整流程

状态含义：“稳定可演示”用于已有实现和测试支撑、主要不依赖临场模型输出的操作；“能用但偶尔出错”表示真实链路已有成功证据但仍依赖模型/外部服务，**不是测得的故障频率**；“半成品”表示用户流程缺少关键入口或步骤。所有判断受上述验证范围限制。

### 流程 A：打开 App → 找已有报告 → 查看原件

**状态：稳定可演示；日期排序存在明确缺陷。**

1. 打开前端页面，没有登录步骤。桌面显示左侧添加/浏览、中间查看器、右侧聊天；手机布局显示“浏览/对话”导航。
2. 页面读取文件、成员和服务配置；初次默认进入“日期”视图。也可能恢复本会话之前的筛选和文件链接。无文件、加载中、后端读取失败分别显示不同状态。
3. 选择家庭成员，点击“成员 / 日期 / 科室 / 疾病”标签，展开分组并单击报告。浏览与聊天共用成员筛选。
4. 中间打开该报告的已保存文本、分类、档案归属、处理状态和文本检查结果。
5. 点击“初始文本”核对首次提取；点击“原件”查看图片/PDF/文本来源。图片可缩放；PDF 可翻页、缩放，也可另开原件。
6. 返回档案后保留分类与成员筛选。手机以全屏查看器和“返回档案”完成同样路径。

**AI 介入：**浏览和查看已保存内容时不调用 AI。

**日期限制：**年份在前的支持格式可组成“年 → 月 → 文件”树。现有样本全是 `MM/DD/YYYY`，会保留原字符串并按字符串倒序排列：例如 `10/17/2024` 在 `02/03/2026` 之前。不能将当前库画面称为已正确按时间排序的时间线。

### 流程 B：上传照片/PDF/TXT → AI 录入 → 找到新记录

**状态：能用但偶尔出错；物理实拍照片的端到端质量未验证。**

1. 从首页“照片 / PDF / 文本文件”选择文件，可一次多选。手机使用浏览器文件选择器；是否提供系统拍照选项取决于设备/浏览器，没有独立拍照页面。
2. 当前会话首次提交时弹出处理说明，列出配置的服务，说明原件存储及送往 AI 的内容。点击“继续并处理”才提交；取消不提交本次内容。
3. 后端先保存原件，前端显示“原件已保存、等待处理”，并可打开记录。这还不是 AI 完成归档。
4. 后台按文件排队：提取文字 → 检查疑点 → 提取分类和索引 → 校验依据并保存。前端约每 1.8 秒轮询一次状态。
5. 归档成功后出现标题、四类分类及打开链接；缺失/歧义不必阻止归档。检查失败与归档失败分别呈现。
6. 如果患者姓名不能匹配现有成员，会弹出“姓名有误 / 新成员 / 稍后核对”。可修正文档与姓名，或添加成员及别名。跳过后仍可在所有成员/待处理找到文件。
7. 新归档文件自动进入浏览和聊天可检索范围，不必在聊天里重新附加。

**AI 介入：**步骤 4 的提取、疑点检查、分类归档。TXT 提取本身只是本地解码，后两步仍调用 AI。

**证据边界：**历史真实图片链路通过过，但输入是由样本 PDF 渲染出的 PNG。倾斜、反光、阴影、模糊的实拍纸张尚未验证。归档过程中没有强制逐字段确认页。

### 流程 C：新建一份文本 → 保存归档

**状态：能用但偶尔出错；真实服务下的新建文本完整演示未验证。**

1. 点击“新建文本”，输入标题和正文；此时是本地未保存草稿。
2. 点击“保存并归档”，必要时接受处理说明。
3. 后端保存最初输入，随后 AI 检查和分类，显示处理状态及归档结果。
4. 原始输入保留为来源，之后的人工编辑不会覆盖它。

**AI 介入：**保存后的疑点检查、分类与索引；没有 OCR。

### 流程 D：提问 → 跨报告查找 → 打开证据

**状态：能用但偶尔出错。**

1. 选择聊天成员或“所有家庭成员”，输入自然语言问题并发送。首次发送同样需要处理同意。
2. 显示“正在思考…”。后端自动提供该成员的完整元数据目录与本页对话历史，AI 选择要读取的已保存报告。
3. AI 返回简短回答，必要时补充一般术语解释和信息限制。不是逐字流式输出，要等完整响应返回。
4. 展开“来源”，查看引用片段、报告链接、人工编辑/检查警示和检索覆盖。点击“打开已保存文本”进入同一个查看器，再切到原件。
5. 可以继续追问；切换成员会恢复各自对话。刷新页面会清空对话，但不删除病历。

**AI 介入：**选文档、组织回答、术语解释、最终证据复核；必要时重新转录原件。普通寒暄不一定读取病历。

**适合试录的问题：**“John 的过敏记录是什么？”、“出院记录有没有写二甲双胍暂停和恢复？”、“请列出各次 HbA1c 的日期与数值”。跨报告题须先试录，历史上出现过漏掉中间化验值。

### 流程 E：发现疑点/分类错误 → 人工修改 → 再提问

**状态：半成品；保存与后续读取已实现，重新检查闭环缺失。**

1. 打开报告，查看疑点引用和原因；这不是自动改写，也没有 AI 提供的替换文本。
2. 点击“编辑／补充信息”，手动修改正文和四个分类字段。
3. 点击“保存”。后端校验编辑版本并更新已保存文本和索引；原件、初始提取保留。
4. 返回分类视图可看到新分组；再次提问时会读取最新保存正文。旧回答不重算，会提示来源已变化。
5. **正文修改后检查标记为过期，但没有 Recheck 按钮，也没有对应 HTTP 端点。** 不能演示“修改 → 重新检查 → 疑点清除”。

**AI 介入：**保存动作本身不调用 AI；重新提问才调用。保存不会自动重新抽取症状等临床标签，也不会从正文自动重写四个分类。

### 流程 F：处理失败 → 查看原件 → 重试或人工补录

**状态：能用但偶尔出错；恢复机制有模拟测试，当前真实失败恢复未重验。**

1. 处理失败时看到错误与失败阶段，原件和已取得文字保留。
2. 打开原件，点击“重试处理”，复用同一个文件 ID；已经提取的文字不会再次 OCR。
3. 也可在编辑器手动输入可用正文和分类并保存。原提取失败标记保留，不会伪装为 OCR 成功。
4. 后端重启会将中断中的任务标为失败，用户需手动重试，不是自动续跑全部队列。

**AI 介入：**重试剩余处理阶段。对于已成功归档但正文检查失败/过期的记录，查看器没有单独重查入口。

### 流程 G：管理成员/删除文件

**状态：稳定可演示，证据主要为隔离后端测试和历史模拟 UI 验证。**

1. 点击“添加成员”创建姓名及别名；或选择成员后，通过“成员操作”更新/移除。
2. 移除成员需要确认，保留报告；姓名/别名匹配会影响归组及聊天范围。
3. 删除报告需要在查看器点击“删除记录”并确认；后端成功后才移除。旧链接显示不可用。

**AI 介入：**无。聊天没有删除能力。

### 无法从当前 UI 走通的动作

- 在聊天中附加照片/PDF、把新输入文本保存成文档：没有入口或相应聊天工具。
- 在聊天中执行分类修改：后端保留提案/提交兼容 API，但当前前端不发送 `metadata_action`，也不显示提案或 Apply 控件。须用户自行打开查看器编辑，不能当成可用聊天功能。
- 创建就诊事件并将多文件加入/移到事件：后端 API 和数据结构存在，前端没有组织入口。

### 抽取字段的实际粒度

- **成员**是文档患者姓名，可附唯一姓名/别名匹配的成员 ID；不是完整身份信息表。
- **日期**保留原来写法和精度；竞争日期保留歧义，不用上传时间补齐。
- **科室、疾病**允许多值。症状不自动当疾病。化验报告依据初始文本归到 `Laboratory Medicine / lab00000`，标为 AI 归档类别。
- **症状、病史、诊断、治疗**是带来源的检索词条，不是规范化临床数据库。
- 没有独立结构化的药品通用名、剂量、频次、疗程、停药事件、化验项目/数值/单位/正常范围趋势表，也没有年龄、性别、DOB、MRN、过敏的专用 schema。这些可以存在正文并被问答读取，不能据此宣称已有专门数据模块。

### 问答是否引用来源

**是。** 患者事实的内部 claim 必须引用已读取文件和可匹配的原句；后端拒绝未读文件、无效引用，以及部分不受支持的年份。普通回答默认把来源折叠在“来源”中；模型可额外选择最多两个醒目链接。链接先打开已保存文本，原件从查看器进入。

局限：引文存在性不等于模型改述必然正确；最终语义复核仍是模型执行。没有 PDF 页码/坐标高亮跳转。回答时文件被改动会拒绝过期结果，之后旧回答也会显示来源已变化。

没有发现 embedding、向量数据库、专门 reranker 或外网医学搜索。当前为**完整元数据目录 → 模型选文档 → 读取正文 → 带引文回答**，不能描述成已实现大型向量知识库。

主要依据：[AI 处理](../backend/processing.py)、[归档工作流](../backend/filing.py)、[字段 schema](../backend/models.py)、[问答](../backend/chat.py)。

## 3. 数据录入

| 项目 | 实际状态 |
| --- | --- |
| 图片 | `.jpg/.jpeg/.png/.webp`。验证图片实际格式；**不支持 HEIC**，没有自动转码。 |
| 拍照 | 标准浏览器选文件；没有 `capture` 属性或专用相机界面。实际手机是否能直接调用相机，未验证。 |
| PDF | 多页仍为一份文件，全部页送提取；最多 50 页。加密/损坏/无法渲染的 PDF 会失败。没有只处理前几页的成功降级。 |
| 文本文件 | `.txt`，UTF-8 或 UTF-8 BOM；GBK 等编码不支持，会提示转为 UTF-8 或手动录入。 |
| 手动文本 | 标题+正文草稿，显式保存后才归档、检查和检索。 |
| 大小 | 单文件非空且最多 20 MiB；AI 后续正文/初始文本最多 100,000 字符。超限原件/已得文本可保留，但后续处理失败。 |
| 多选 | 多个文件可批量选择；每个单独建文档。多个照片不会自动合并成一个多页病历。后端只有 1 个归档工作线程，批量处理串行排队。 |
| 人工确认 | 上传后自动处理/归档，不先停在逐字段审阅确认页。疑点显示原句和原因，用户后续自行编辑；患者姓名不匹配会另弹成员核对。 |
| 保存层 | 原始字节、初始提取、当前文本、分类和索引在 SQLite 内保存；不是按患者建出的实体文件夹。 |

### 重复上传到底怎么处理

**只有操作幂等，没有按文件内容全局去重。**

- 同一次上传的失败重试保留 `Idempotency-Key`，后端返回同一文件 ID；同一键换内容会报冲突。
- “重试处理”也复用现有 ID。已有文字时不再次提取。
- 用户重新打开选择器再选同一份文件，会生成新键，**创建第二份文档和默认档案**。库中源文件 SHA-256 不是内容去重的唯一约束。
- 同日同科室不会自动合并。旧问答验收中的“重复文档不重复计算事件”是问答行为，不代表存储侧已去重。
- 批次中一个上传失败会停止这轮后续提交；重试保留各文件键，已收到的文件不会因为同一轮重试再多建一份。刷新后这些前端重试状态不持久化。

依据：[导入 UI](../src/import/ImportPanel.tsx)、[导入 API](../backend/api.py)、[Library.create](../backend/storage.py)、[schema](../backend/schema.sql)。

## 4. 病历浏览和修改

### 有哪些视图

| 视图/能力 | 代码实际状态 |
| --- | --- |
| 成员、日期、科室、疾病 | 四个可折叠分类视图；同一文件可出现在多个科室/疾病分组，身份相同，不是物理复制。 |
| 日期/时间线 | 有分类树，没有可视化事件时间线。年份在前的支持格式按年/月组树；美式样本格式排序有上述缺陷。 |
| 待处理 | 包含缺失/歧义、处理失败、检查疑点/过期、成员待核对等。疾病为空本身不强制待处理。 |
| 就诊事件/档案 | 后端有 `patients → medical_records → documents` 及显式分组/移动 API；前端只显示档案摘要和文档数量，没有事件列表/编辑/多文件分组入口。普通导入默认一文件一档案，不能认定十份样本已整理成三个事件。 |
| 专门用药列表 | **没有**。聊天可以回答“某日期记录的药物”，不是可维护的当前用药模块。 |
| 化验趋势图 | **没有**。聊天可复述多个日期的数值；没有独立图表或计算引擎。 |
| 当前文本、初始文本、原件 | 三个标签；PDF 翻页/缩放，照片缩放。疑点以引用块呈现，没有文内位置高亮。 |
| 独立病历摘要页 | **没有**。可在聊天请求摘要。数据库 `record_abstracts` 是证据索引，不是 AI 生成的医疗叙事。 |
| 文本关键词搜索框 | 浏览面板没有，检索入口主要是分类浏览和聊天。 |

### 哪些字段可以编辑

- 文档的**当前正文、患者姓名、日期、科室、疾病**。科室/疾病用英文逗号分隔输入多值。
- 成员资料的**显示姓名与别名**；新增、更新、移除走独立表单/操作。
- 已保存文档标题没有编辑入口；新建文本可在保存前填标题。档案标题/归属重组没有前端编辑入口。
- 不能修改原件或初始提取，不能通过独立字段修改药物/化验项目；要更改这些内容只能编辑正文。
- 未改动的分类尽量保留原出处；有意改动标为用户提供。没有完整版本历史或差异对比界面。

### 修改后问答会不会跟着更新

**新一轮问答会读取最新保存内容；已有回答不会自动更新。**

1. 保存时正文/分类及文档索引更新，档案索引按新版本刷新。正文变更后旧的 AI 临床词条被移除，使用最新正文，避免继续保留旧内容作为标签。
2. 问答工具按文件 ID 读取当前已保存正文；未保存草稿不参与检索。
3. 但是保存后**不会再调用分类模型重建症状/病史/诊断/治疗词条**，聊天首轮目录只发送这四类 clinical_index，而不发送整个新正文。因此新增事实若没有反映在标题/分类中，模型可能没有选择读到它；“自动重新索引”不等于完整语义重抽取。
4. 旧聊天仍保留原回答，并显示来源变化提示；用户需要重新提问。回答生成中源文件改动会使请求失败，避免返回旧版证据。
5. 正文修改使检查过期；没有单独 Recheck。只改分类不应把原疑点清除。

未保存离开使用浏览器确认框，只能“放弃并离开 / 取消后返回编辑，再手动保存”，不符合 PRD 的直接三选项 Save/Discard/Stay。保存错误保留草稿；版本冲突要求重开文件，本次未实际验证保留草稿后的完整冲突恢复体验。

依据：[分类浏览](../src/library/LibraryBrowser.tsx)、[日期/分组逻辑](../src/library/browsing.ts)、[查看器](../src/import/Viewer.tsx)、[手动保存 API](../backend/api.py)、[检索目录](../backend/chat.py)。

| 风险 | 已知事实/未验证项 | 对录制的影响与准备 |
| --- | --- | --- |
| 外部服务慢、限流、备用失败 | 历史真实出现过主服务 429；每次请求可等 180 秒；备用失败可直接结束。备用服务图片输入是否可用未验证，文字问答成功不证明 OCR 备用有效。 | 正式录制前用目标文件/问题试跑。导入和回答留剪辑余量，保留失败及重试镜头备选；不要承诺即时完成。 |
| 批量长队列 | 归档只有一个 worker，单文件至少提取/检查/归档三阶段。 | 不在主镜头从零等待 10 份文件；预置样本库，再单独演示一份真实上传。 |
| 日期排序错误 | 当前全部 10 份样本的美式日期按字符串排序，2026 记录在列表后部。 | 不声称可靠时间线。若以后修复要用这些原日期验证；不要静默改原件来制造正确排序。 |
| 没有可拍照片/疑点/第二成员 | 当前库只有 10 PDF、一成员、零疑点。历史 PNG 为渲染图片。 | 另外准备实拍 JPG/PNG 并试识别；第二成员和疑点使用清楚标注的虚构资料，保留独立可恢复演示库。 |
| AI 检查误报 | `photo-retest.json` 中将 DOB 03/14/1956、报告日期 03/08/2023、年龄 66 标成年龄错误；实际上未满 67，66 并不矛盾，原因自身还矛盾。 | 不能宣称疑点检查可靠发现所有错误。优先验证“年龄 151”等明确输入；不要展示这个年龄误报作为正确能力。历史 artifact 的整体 passed 不代表每一句都正确。 |
| AI 词义改述/漏读 | 历史趋势题漏过中间值，后来提示词加强；引文校验不能验证整段改述。 | 用具体日期/项目提问并检查每个引用；不要只凭历史正则 passed 录旁白。 |
| 旧脚本与当前能力冲突 | 原测试要求年龄/住院时长计算和“改善/下降”等判断；当前提示词禁止独立计算、医学分析和结论。 | 脚本改成“记录写了什么、各次值是多少”，不把计算/诊断当亮点。一般术语解释与患者事实分开。 |
| “最近/上个月”问题 | 样本最后日期为 2026 年 2 月，录制时是 10 月底或 11 月；`test/Demo script.txt` 有 “Last month”。 | 不能期待返回最近一个月就诊；明确问“最近一份已保存记录”或具体日期。最新用药清单也只能说“某次记录中的清单”。 |
| 重复上传增加条目 | 新选择同文件会新建条目，不做内容去重。 | 多次重录前恢复独立演示库，或确认删除多余演示条目；不要把重复测试的问答结果说成数据库去重。 |
| 姓名核对弹窗抢镜 | 无精确姓名/别名匹配会自动弹核对；稍后处理只保存在本页状态，刷新可再次出现。 | 预先核对 `SMITH, JOHN`、`John Smith` 等实际别名与目标成员；需要展示弹窗时专门安排，不临场处理意外分配。 |
| 未保存/旧版本状态 | 编辑离开会弹浏览器确认框；轮询、归档、改成员可能使编辑版本过期；源文件修改中问答可失败。 | 按“等待处理完成 → 编辑保存 → 再提问”拍摄；不要同时改源文件并等回答。 |
| 编辑后警告不消失 | 正文保存使检查 stale；无 Recheck，旧疑点不会形成重新验证的清除闭环。新增正文也不会自动重建临床标签。 | 改完后只展示保存文本、保留来源及新读取；不能拍“检查已全部通过”。必要时在明确指向该报告的问题中验证新内容。 |
| 聊天清空/上下文超限 | 刷新清空对话；没有“新对话”按钮；长历史和元数据超过 300,000 字符会失败，错误提示虽建议新对话但 UI 没入口。 | 分段录制前计划刷新时机，截取需要保留的回答；长会话试录避免一直累积。 |
| 来源默认隐藏、原件未加载 | 证据在折叠区；PDF 预览延迟加载并依赖打包的 worker/字体资源。 | 试走完整来源路径和 PDF 第 2 页；字幕不能说“没有引用”，也不要漏拍展开动作。 |
| 手机/上线环境未验证 | 历史手机检查主要是 Edge 模拟视口；真实手机、Linux 部署未验证。开发代理在 Vite dev 中配置，不能由 build 成功推定静态部署的 `/api` 已通。 | 桌面本地 dev 是当前证据最足的录制环境。若用手机，先验证后端可达与 HTTPS/文件选择；`crypto.randomUUID()` 在目标手机 HTTP 环境是否可用未验证。 |
| 截图/日志包含内容 | `data/backend.log` 记录 AI 返回内容；本地还有历史 SQLite 备份/验收副本。应用内删除不承诺清掉这些副本。 | 演示用虚构资料，避免把服务密钥窗口录入；不要旁白承诺“删除会清除所有备份和日志”。 |

建议主线镜头：**已有档案全景 → 上传一份已试跑的照片 → 处理完成与分类 → 具体历史问题 → 展开来源 → 原件对照**。人工编辑和“信息不足”可作为补充镜头。拍摄前必须补验真实照片、当日服务、选定跨文档问题；Recheck、趋势图、自动事件合并、聊天保存/改分类当前不适合作为已完成功能展示。
